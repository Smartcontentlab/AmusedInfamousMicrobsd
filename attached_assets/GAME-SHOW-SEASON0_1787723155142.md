## 2. Five Layers

### Layer 1 — Game Master
**File:** `game-show/master.js`

Responsibilities:
- Challenge creation and distribution
- Permission management (who can use what tools)
- Score calculation based on REAL outcomes (not self-reporting)
- Event injection (market crashes, opportunities, crises)
- Elimination decisions

### Layer 2 — Contestants
**Files:** `contestants/*.md` + personal memory files

Responsibilities:
- Receive challenges
- Make decisions based on personality + skills
- Execute actions through the Business Toolbox
- Learn from outcomes (adaptability)

### Layer 3 — Personal Skills & Memory
**Files:** `contestants/<id>/memory.md` + skill loadouts

Responsibilities:
- Persistent memory of past decisions
- Learned preferences and patterns
- Skill-specific knowledge

### Layer 4 — Business Toolbox
**Files:** `game-show/toolbox.js` + MCP server configs

Responsabilities:
- Unified API for all tools
- Permission enforcement
- Rate limiting and cost tracking
- Tool unlock progression

### Layer 5 — Real Business Infrastructure
**External services:**
- Supabase (database per contestant)
- Vercel (website hosting)
- Stripe (payments)
- GitHub (code repos)
- n8n (automations)
- agent-browser (web interaction)

## 4. Database Schema (Per Contestant in Supabase)

```sql
-- Each contestant gets their own schema
CREATE TABLE customers (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  email TEXT NOT NULL,
  name TEXT,
  source TEXT,
  created_at TIMESTAMPTZ DEFAULT now()
);

CREATE TABLE products (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  name TEXT NOT NULL,
  price INTEGER NOT NULL, -- cents
  stripe_product_id TEXT,
  stripe_price_id TEXT,
  type TEXT DEFAULT 'one_time', -- one_time, subscription
  status TEXT DEFAULT 'draft',
  created_at TIMESTAMPTZ DEFAULT now()
);

CREATE TABLE orders (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  customer_id UUID REFERENCES customers(id),
  product_id UUID REFERENCES products(id),
  stripe_payment_intent_id TEXT,
  amount INTEGER NOT NULL,
  status TEXT DEFAULT 'pending',
  created_at TIMESTAMPTZ DEFAULT now()
);

CREATE TABLE leads (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  email TEXT,
  name TEXT,
  source TEXT,
  status TEXT DEFAULT 'new', -- new, contacted, qualified, converted
  score INTEGER DEFAULT 0,
  created_at TIMESTAMPTZ DEFAULT now()
);

CREATE TABLE campaigns (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  name TEXT NOT NULL,
  type TEXT, -- email, social, ads, content
  status TEXT DEFAULT 'draft',
  metrics JSONB DEFAULT '{}',
  created_at TIMESTAMPTZ DEFAULT now()
);

CREATE TABLE content (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  title TEXT NOT NULL,
  type TEXT, -- blog, video, social, email
  status TEXT DEFAULT 'draft',
  metrics JSONB DEFAULT '{}',
  created_at TIMESTAMPTZ DEFAULT now()
);

CREATE TABLE analytics_events (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  event_type TEXT NOT NULL,
  properties JSONB DEFAULT '{}',
  created_at TIMESTAMPTZ DEFAULT now()
);
```

## 5. Game Master Scoring (Real Outcomes, Not Self-Reporting)

### What the Game Master Checks

| Metric | Source | Scoring |
|---|---|---|
| **Website exists?** | Vercel deployment check | 0 or 10 points |
| **Website works?** | agent-browser smoke test | 0-5 points |
| **Traffic?** | Analytics API | 0-10 points (log scale) |
| **Signups?** | Supabase customers table | 2 points per customer |
| **Revenue?** | Stripe payment intents | 1 point per $10 |
| **Conversion rate?** | Orders / Visitors | 0-15 points |
| **Cost efficiency?** | Revenue / Spend | 0-10 points |
| **Time to first customer?** | Timestamp comparison | 0-10 points (faster = more) |
| **Idea quality?** | Judge LLM (rubric) | 0-20 points |
| **Adaptability?** | Changed approach after failure? | 0-10 points |

### Elimination Mechanics

- Each contestant starts with 3 lives
- Lowest scorer each round loses a life
- 0 lives = eliminated
- Tiebreaker: adaptability score (who learned more from failures)

## 7. Scoring Formula

```
Final Score = (profit * 0.25)
            + (growth_rate * 0.20)
            + (customer_retention * 0.15)
            + (founder_efficiency * 0.15)
            + (capital_efficiency * 0.10)
            + (resilience * 0.10)
            + (company_value * 0.05)
```

## 10. Key Insight

> "The world produces the score. Not the LLM."

This is the core differentiator. The Game Master doesn't ask agents to report success. The Game Master **checks the infrastructure**:
- Does the website exist? → Vercel API check
- Is there traffic? → Analytics query
- Did anyone sign up? → Supabase row count
- Did anyone pay? → Stripe payment intents
- What's the conversion rate? → Calculated from real data

Agents can't bullshit their way to success. The environment is the judge.
